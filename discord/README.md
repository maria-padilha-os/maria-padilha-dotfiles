# Discord (opt-in, unsupported)

Discord has no supported API for arbitrary CSS. It does not load user
stylesheets, and its built-in Appearance settings only change a few predefined
options. The only way to load `theme.css` is a third-party **client mod** that
injects CSS into the running Discord client. This theme is unsupported by
Discord.

This repository does **not** install, patch, update or configure Discord, Vencord,
BetterDiscord, Vesktop or any other client. Nothing under `discord/` is linked
by `bin/padilha-dots`; installation is a manual, explicitly opt-in choice made
outside this checkout.

> [!WARNING]
> Client modifications are against Discord's Terms of Service. Both Vencord and
> BetterDiscord say so in their own documentation. They also report that bans are
> rare or unknown in practice, but that is not a guarantee. If losing your
> account would be a disaster for you, do not use any client mod.

The static CSS in this directory does not read a token, account, message,
local storage or the Discord API. It has no JavaScript, no network request, no
`@import`, no remote asset, no updater and no auto-injection. The account risk
comes from the mod that loads it, not from the stylesheet's contents.

## What the theme does

`theme.css` maps the generated Material You palette onto Discord's own CSS
variables. It recolours surfaces, text, links, mentions, focus rings,
scrollbars and a few common controls. It does not hide elements, change the
layout, add images, or touch the chat/service logic.

The theme reads the same `--lilith-*` custom properties that
`padilha-theme` writes for Firefox. The complete palette is generated by
`padilha-theme` in `maria-padilha-de`; this repository does not generate it.
The names consumed here include `--lilith-scheme`, `--lilith-bg`,
`--lilith-surface`, `--lilith-surface-container*`, `--lilith-on-surface*`,
`--lilith-primary*`, `--lilith-outline*` and `--lilith-error*`. The fallback
block also carries the secondary, tertiary and inverse roles so a partial
generated palette still resolves.

If the generated block is missing, the theme falls back to the dark palette in
`hypr/scheme/default.lua`. That is enough to keep the client readable, but it is
not the current wallpaper palette.

## Get the generated palette

The palette is the `chrome/lilith.css` file already written for Firefox. If you
have applied a theme, it exists at:

```text
~/.mozilla/firefox/<profile>/chrome/lilith.css
```

If not, run the normal theme command from the `maria-padilha-de` checkout (it is
not run automatically by this repository):

```sh
padilha-theme apply --wallpaper "$(cat ~/.local/state/caelestia/wallpaper/path.txt)"
```

Then copy only the `:root { ... }` declarations from that file. Do not copy an
`@import` line even if one is present; Discord's theme loader does not reliably
resolve local file imports. If you have no palette handy, skip this step and use
the fallback.

## Install Vencord manually (recommended)

1. Install Vencord yourself from the official
   [download page](https://vencord.dev/download/). This repository does not run
   the installer or patch Discord.
2. In Discord, open **Settings → Vencord**, enable **Enable Custom CSS**, and
   click **Edit QuickCSS**.
3. Paste the contents of [`theme.css`](theme.css) into QuickCSS.
4. Paste the generated `:root { ... }` palette block anywhere in the same
   QuickCSS sheet. The generated `:root` has higher specificity than the
   theme's `:where(:root)` fallback, so it wins regardless of order. Keeping it
   near the top is easiest to maintain.
5. Save, then toggle Custom CSS off/on or restart Discord if the change does not
   appear.

To use a file instead of QuickCSS, open **Settings → Themes → Local Themes →
Open Themes Folder**, copy `theme.css` into that folder as
`maria-padilha.theme.css`, and insert the generated `:root` block immediately
after the theme's meta comment (the `/** ... */` block). Enable the theme in the
same panel. Vencord also accepts BetterDiscord themes, so this is the same file.

On a typical Linux install the Vencord themes folder is under
`~/.config/Vencord/themes`, but Discord branch, Flatpak, Snap and Vesktop use
different roots. Prefer Vencord's **Open Themes Folder** button over guessing
the path.

## Install BetterDiscord manually

1. Install BetterDiscord yourself from the official
   [site](https://betterdiscord.app/) or its
   [documented CLI](https://docs.betterdiscord.app/users/guides/cli). This
   repository does not run the installer or patch Discord.
2. Open **Settings → BetterDiscord → Themes → Open Themes Folder**. On Linux
   the folder is normally `~/.config/BetterDiscord/themes`.
3. Copy `theme.css` there as `maria-padilha.theme.css`.
4. Edit the copy and insert the generated `:root { ... }` palette block
   immediately after the opening meta comment, before the `:where(:root)`
   fallback. BetterDiscord requires the meta block to be the first thing in the
   file, so do not put the palette above it.
5. Enable the theme, then restart Discord if the change does not appear.

## Updating the palette

The theme does not auto-update and does not watch the generated file. After a
wallpaper or palette change, run `padilha-theme apply` again and replace the
palette block you pasted into QuickCSS or the local theme. The fallback values
in `theme.css` stay in the checkout and are not rewritten by the generator.

## Removing it

- Vencord QuickCSS: clear the custom CSS and disable **Enable Custom CSS**.
- Vencord local theme: disable or delete `maria-padilha.theme.css` in the
  themes folder.
- BetterDiscord: disable or delete `maria-padilha.theme.css` in the themes
  folder.
- No Discord installation files were modified by this repository.

## Verification checklist

These checks are static; they do not start Discord or a client mod.

```sh
sh tests/ci.sh
python3 tests/discord_theme.py
```

After a manual install, check in Discord:

- [ ] The server list, channel sidebar, chat area, member list, menus and
      settings use the generated surface colours rather than Discord's default
      blurple-grey.
- [ ] Normal text, muted text, links and mentions are readable in both a light
      and a dark generated palette (change the wallpaper and re-apply the
      palette to test both).
- [ ] Focus remains visible when tabbing through buttons, the message box and
      menus.
- [ ] No remote request is made by the theme; it has no `@import`, `url()`,
      font or image.
- [ ] Disabling the theme or Custom CSS restores the stock Discord appearance.

If a Discord update breaks the selectors, disable the theme and use stock
Discord. The CSS variables are the most stable part; per-element class names are
not. This theme intentionally avoids broad class-name selectors, but Discord can
still rename or restructure its tokens.

## Why there is no install script

An installer would have to discover a Discord installation and patch or inject
into it. That is exactly the kind of silent, privileged, auto-updating behaviour
this repository must not add. It would also write outside this checkout. The
manual steps above keep the decision, the client patch and all updates in the
user's hands.
